# SIHTRACK — Extreme Weather Intelligence & Tracking Platform
### Smart India Hackathon 2026 · Problem Statement SIH26078
**AI-Driven Spatio-Temporal Tracking of Extreme Weather Anomalies in Medium-Range Forecasts**

Concept cycle: **DETECT → IDENTIFY → TRACK → ANALYSE → PREDICT → VISUALISE → ALERT**

> ⚠️ **DEMO / SIMULATED DATA.** This prototype is not connected to IMD, NCMRWF, ECMWF or any
> operational system. Every field, event, track, ETA, statistic and alert is generated by a
> deterministic in-browser demo engine. No value here is an official forecast.

## 1a. Google Maps key setup (required)

The basemap is the **Google Maps JavaScript API**, loaded on demand from
`src/lib/googleMaps.ts`. You need a key before the map will draw.

1. In [Google Cloud Console](https://console.cloud.google.com/), create or pick a project
   and **enable billing** — the Maps JavaScript API requires an active billing account even
   at free-tier usage limits.
2. Enable **Maps JavaScript API** for that project.
3. Create an API key, then **restrict it**:
   - *Application restrictions* → **HTTP referrers** → add the origins you serve from,
     e.g. `http://localhost:5173/*` and `http://localhost:*/*` for local work.
   - *API restrictions* → **Maps JavaScript API** only.
   Never ship an unrestricted key.
4. Put the key in a local env file (already git-ignored):

   ```
   .env.local
   ─────────
   VITE_GOOGLE_MAPS_KEY=your_key_here
   ```

5. Restart the dev server — Vite only reads env files at startup.

The key is client-side by definition, so referrer and API restrictions are the only real
protection. If the key is missing, invalid, or blocked, the map shows an inline error panel
that names the cause (missing key / billing / blocked script) and offers a retry; the Events,
Analytics, Forecast, Alerts and About pages keep working regardless.

## 2a. One hazard, one event, one map

The map is deliberately narrow about what it shows, in two steps.

**First, one weather type.** A selector docked on the left edge of the map
(a horizontal strip on narrow screens) lists all ten hazards — Heat, Convection,
Cyclone, Rainfall, Flood, Wind, Cold, Pressure, Drought, Compound — each with a
Lucide icon and its own accent colour.

**Then, one event at a time.** Whatever type is chosen, the map draws a single
event — its marker, past track, forecast track, uncertainty corridor, arrival
times and detail drawer all describe that one event. The other events are never
drawn alongside it.

Because the map only carries one event, it also carries the way to reach the
others:

- **‹ › step buttons** walk the current set, and wrap around at both ends
- **the event list** names every event available right now — click to switch
- **the counter** reads `Event 3 of 14`, so it is always clear that more exist
- picking a hazard type narrows that set (Heat → 2 events, Rainfall → 3)
- the header names the type, the position and the event ID, e.g.
  `All types · event 3 of 14 · EX-1044`
- the KPI strip rescopes to the current type

Switching event moves the map, the selection and the detail drawer together, so
nothing on screen ever describes an event that is not the one being shown.

The type selector is a real radio group, so the arrow keys move between types.
The step buttons are labelled `Previous event` / `Next event` for screen readers
and are reachable by `Tab`. Note that `←` / `→` stay bound to **timeline
scrubbing**, not to event switching, so scrubbing the clock and walking the
event set never fight over the same key.

This is the same rule twice: ten marker colours on one map, and then a dozen
markers of the same colour, are both things a first-time reader cannot decode.
Answering one hazard, then one event, keeps the overview exactly one click away
via **All types**.

### The uncertainty corridor

The blurred band around the forecast line is the swathe of possible positions.
Its width is a function of **forecast lead time from NOW**, not of wherever the
timeline cursor is parked: roughly 25 km wide at the present moment, fanning out
to about 140 km at the +72 h horizon. It is therefore drawn once per event and
deliberately does *not* move as you scrub — the cursor moves the marker along the
best-guess track while the band continues to describe the full uncertainty ahead
of the present. That keeps "how sure are we" separate from "when are you
watching".

### Map architecture

Four deliberate choices keep the map from ever showing a blank screen:

1. **The basemap is Google's vector rendering, not a symbol layer we fetch.** The Maps
   JavaScript API draws the base map itself, so there is no glyph server to reach and no
   style to fail validation. State labels and event markers are DOM elements positioned
   locally, so the app's own text never depends on a remote font or sprite.
2. **A load watchdog guarantees readiness.** If `tilesloaded` never arrives, a 6 s timer
   still resolves the loading state and publishes the basemap status.
3. **The loader distinguishes failure modes.** A missing key, a billing problem and a
   blocked script are reported as three different messages, each with a retry, so a
   misconfiguration is never mistaken for a rendering bug.
4. **Weather fields are rasterised on the CPU at 512×512** and attached as
   `google.maps.ImageMapType` overlays, geographically cropped so each tile requests only
   the field pixels it covers. Overlays are pushed in a fixed precedence order (risk and
   anomaly most transparent) and the layer list is rebuilt — not mutated in place — because
   Google exposes no public way to reorder `overlayMapTypes`.

Two details are worth knowing if you touch the overlay or label code:

- `map.getProjection()` is **not** reliably populated on the current Maps JS API, so
  DOM-marker placement, state-label culling and the corridor ribbon all use a local
  Web-Mercator projection (`projectPoint`) computed from `getCenter()`/`getZoom()`.
  Bearing and tilt are never enabled, so centre-is-container-middle holds. Marker
  clustering was removed along with the multi-marker map: the engine now draws a
  single marker, so `cluster` is hard-coded to `false` and there is nothing to group.
- `addListenerOnce` no longer exists on `Map`; one-shot listeners are built from
  `addListener` plus `remove()`.

### Why it stays in sync
`currentTime` is the **only** time state. Events are pure functions of it
(`resolveEvent(seed, t)`), the raster fields are built from the events at `t`, the charts
plot the same series around `t`, and the alert/risk/compound panels read the same snapshot.
Nothing can drift out of step because nothing stores its own copy.

## 4. Connecting a real backend

`src/services/api.ts` is shaped exactly like the FastAPI surface it would replace:

```
GET /api/v1/health
GET /api/v1/events?t={hours}          GET /api/v1/events/{id}
GET /api/v1/field/{layer}?t={hours}   GET /api/v1/field/wind-vectors?t={hours}
GET /api/v1/regions/risk?t={hours}    GET /api/v1/compounds?t={hours}
GET /api/v1/alerts?t={hours}          GET /api/v1/stats?t={hours}
GET /api/v1/analytics/history?t={hours}
GET /api/v1/analytics/outlook?t={hours}
GET /api/v1/meta
```

Set `USE_MOCK_API = false` and `VITE_API_BASE` to the live host — no UI file needs to change.
Intended production stack: FastAPI · Python/NumPy/Pandas/xarray · PyTorch (ConvLSTM +
autoencoder) · PostgreSQL/PostGIS.

## 5. How to read the application in 30 seconds

The full version lives in the app under **About**, but the essentials are:

| Question | Where to look |
|---|---|
| What is happening? | The map. It shows one detected event at a time, with a switcher to the rest. |
| How serious is it? | Marker colour and the legend: green → yellow → orange → red. |
| Where is it going? | Press **Track This Event**. The dashed line is the forecast. |
| When will it arrive? | The drawer lists each downstream region with its estimated arrival. |
| How confident is it? | The confidence figure falls as the forecast gets further away. |
| How has it changed? | Drag the timeline under the map, or press `Space` to play. |

Severity classes are built from a composite score: **Normal** below threshold,
**Moderate** 55–67, **High** 68–81, **Extreme** 82 and above.
